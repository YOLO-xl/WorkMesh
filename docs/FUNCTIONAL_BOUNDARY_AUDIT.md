# WorkMesh 功能边界审计

> 审计时间：2026-11-09  
> 审计基线：`a4c9b25`（v0.7.0-dev）  
> 方法：逐模块读代码 + 核对调用链 + 跑测试 + 查实际库数据。未使用真实 ES / Prometheus / LLM Key，因此“外部联调”一律不算完成。

## 1. 结论摘要

WorkMesh 现在不是“只有界面”的原型。核心闭环已经真实成立：

**导入反馈 → 统一证据模型 → 关联证据 → 规则诊断 / 簇报告 → 报告归档 → 处理状态 → 周期汇总**

但能力边界也很清晰：

- 真正完成的是**本地单工作空间、SQLite、同步执行**这条链路。
- ES / Prometheus 连接器是**代码完成 + mock/样例验证**，没有真实实例联调。
- LLM 诊断链路是**代码完成 + 注入式测试**，没有真实 Key 的线上结果。
- 分析页、聚类页、周期报告都有明确的数据量上限或功能缺口，不能按“生产级”理解。
- 没有账号、权限、审计、任务队列、API；当前是本地单用户工作台。

测试基线：`126 passed`。UI 没有进入自动化测试套件，现有 UI 结论来自手工 AppTest / 浏览器验证。

## 2. 成熟度分级

| 级别 | 定义 |
|---|---|
| A. 已闭环 | 代码、数据层、服务层、UI 均可用；有自动化测试；本地真实数据跑通 |
| B. 已实现未联调 | 代码和 mock/样例测试存在，但依赖外部实例或凭据，真实环境未验证 |
| C. 初步实现 | 主路径可用，但有明显上限、缺页、缺状态或缺少自动化测试 |
| D. 仅接口/未开始 | 只有抽象接口、文档计划或占位，无可用业务闭环 |

## 3. 逐域审计

### 3.1 数据接入与存储 — A / C

**已闭环**

- CSV / Excel 读取、编码兜底（`utf-8-sig` / `utf-8` / `gb18030`）。
- 字段别名识别、手动映射、标准化、必填校验、文件内重复检测。
- 导入批次、文件 hash 防重复导入、单条失败不回滚整批。
- SQLite 持久化，`WORKMESH_DB_PATH` 可切库；Schema v1 → v6 迁移可用。

**边界**

- 整文件读入内存（`read_uploaded_file` 的 `getvalue()` + `pd.read_csv`），没有分块、没有后台任务、没有断点续传。
- 只做“同一文件 hash 防重”，不做跨文件内容去重/合并/覆盖。
- 空单元格从 pandas 进入 `raw_payload` 时会变成 `NaN`，含 JSON 字段的批量写入可能部分失败；本轮 100 条模拟导入中 4 条无码记录就触发了这个问题。
- 导入 UI 的完整流程没有自动化测试；测试覆盖的是 `data_import_service` 函数。

**判断**：日常小文件导入可用；万级、十万级或无人值守导入不具备。

### 3.2 反馈分析 — A / C

**已闭环**

- 总量、独立用户、产品数、版本数来自全量 SQL 聚合。
- 错误码 / 版本 / 平台 Top 10 分布。
- 现象分布、功能提及分布、按现象下钻。
- 最新反馈列表。

**边界**

- 现象/功能分析只取 `list_feedback(page_size=500)` 的前 500 条，不是全量；页面没有分页或时间筛选。
- 没有 UI 自动化测试。
- 图表是自绘条形图，没有趋势预测、异常检测或对比周期。

**判断**：适合看样本和演示；超过 500 条后“现象分布”会静默失真。

### 3.3 问题聚类 — A / C

**已闭环**

- 有错误码：按「产品 + 错误码」归并。
- 无错误码：现象词典 + 功能实体 + 3-gram 相似度 + 版本/平台一致性加权，超过阈值才归并。
- 未归类池、孤立反馈、簇关键词、现象分组、影响面、时间集中度。
- 10 项单元测试，100 条无码样例有回归。

**边界**

- `ClusterService.build` 固定最多读取 500 条（`list_feedback(page_size=min(limit, 500))`），没有分页/增量窗口。
- 没有人工合并、拆分、改名、写回标签；簇 ID 由成员集合哈希生成，数据一变就可能变。
- “簇报告”里的 LLM 分支实际固定 `use_llm=False`，簇报告是规则汇总，不是 LLM 诊断。
- 簇报告快照按「产品 + 错误码 / 无码按标题」归并，标题变化会影响历史连续性。
- 聚类页没有自动化 UI 测试。

**判断**：算法可用，适合中等数据量；不能作为稳定的问题主数据，因为人工无法纠错。

### 3.4 统一证据与关联 — A

**已闭环**

- `Evidence` 统一 feedback / log / metric / trace / change / note 六类。
- Trace ID / Request ID 强关联；UID / 错误码 / 服务名需在时间窗内；时间接近只加分。
- 关联结果落库，保存分数、命中键、理由、强弱、context 关系。
- 事实与假设分开；指标/变更/备注只能作为上下文证据。
- 单元测试覆盖模型、仓储、服务、关联规则。

**边界**

- 关联阈值是代码常量（`DEFAULT_WINDOW_MINUTES=30`、`DEFAULT_MIN_SCORE=30`、权重固定），没有场景化配置或校准面板。
- 候选证据 SQL 粗筛上限 200，精算结果上限 50；超出后可能漏证据。
- 只支持“单条反馈为锚点”的上下文，没有“以簇为锚点”的跨反馈上下文。
- 真实 ES / Prometheus 证据没有进来过，当前库里只有 14 条样例证据、6 条关联。

**判断**：这是当前最扎实的一块，但“阈值是否适合真实业务”尚未验证。

### 3.5 外部连接器 — B / D

| 连接器 | 状态 | 实际能力 | 边界 |
|---|---|---|---|
| Elasticsearch | B | 地址、超时、API Key / Basic Auth、`verify_certs`；按 index、UID、错误码、时间窗、keyword 查询；日志标准化 | 未真实联调；没有 Trace ID / Request ID / service / level 过滤；没有分页/search_after；没有 Bearer / Cloud ID；连接配置只在页面临时填写 |
| Prometheus | B | instant / range query；Bearer / Basic；注入 `http_get` 离线测试；vector / matrix / scalar / string 解析 | 未真实联调；没有告警、元数据、series 浏览；matrix 只保留最近 `max_points` 点 |
| OpenSearch | D | 无 | 只有路线图 |
| Loki | D | 无 | 只有路线图 |
| Jaeger / Tempo | D | 无 | 只有路线图；`trace` 证据类型已在模型里预留 |

`BaseConnector` / `ConnectorRegistry` 是真实可扩展的接口，不是业务完成。目前只注册了 ES 和 Prometheus。

### 3.6 诊断 — A（规则）/ B（LLM）

**已闭环**

- 规则诊断：事实、推断、下一步；引用证据 ID。
- LLM 诊断：服务商预设、模型、超时、测试连接；LLM 输出必须引用证据清单内 ID，引用不存在 ID 直接打回；事实仍以规则层为准。
- LLM 不可用时自动退回规则诊断，并给出配置提示。
- 注入式 LLM 测试覆盖解析、引用校验、回退。

**边界**

- 没有真实 LLM Key，线上诊断质量未知。
- `_next_steps` 里硬编码了 `rtmp` / `cdn` 判断，明显偏直播场景；非直播反馈只能落到“扩大窗口/补证据”的通用建议。这正是需要故障场景模型的原因。
- 没有历史故障检索、知识库、根因候选排序、提示词评测。
- LLM 只用于单条诊断；簇报告和周期报告不调用 LLM。

**判断**：诊断“管道”完成，诊断“领域知识”还很薄。

### 3.7 报告与处理闭环 — A / C

**已闭环**

- 单条诊断报告：归档、关键词/生成方式检索、下载、两步删除、内容 hash 去重。
- 簇报告：整簇汇总、抽样 3/5/8、快照对比、筛选、下载、删除。
- 处理状态：待处理/已处理/已忽略、负责人、备注、批量处理、已处理锁定+重新打开。
- 周期报告：按日期区间汇总反馈/问题/无码现象/报告处理状态，全产品/单产品，hash 去重、检索、下载、删除。

**边界**

- 周期报告没有处理状态跟踪（`report_tracking` 只允许 `feedback` / `cluster` 两个 scope）。
- 周期报告只能手动生成，没有定时任务、订阅、失败重试。
- 诊断报告和簇报告列表默认 limit 100/200，没有真正的分页 UI。
- 报告指标“待处理”只统计可跟踪的诊断+簇报告，周期报告不计入。
- 周期报告 UI 没有自动化测试；本次只做了 AppTest 手工冒烟。

**判断**：报告归档链路完整；周期报告是“汇总器”，不是“监控任务”。

### 3.8 LLM 配置 — A / B

**已闭环**

- 环境变量优先、本机 `.workmesh/llm.local.json` 兜底；目录 0700、文件 0600、原子写。
- OpenAI / DeepSeek / 通义 / Kimi / 智谱 / SiliconFlow / Ollama / 自定义。
- 保存、清除、测试连接；`report_center` 测试覆盖配置隔离和 fake client。

**边界**

- 没有真实 Key，测试连接只验证到“客户端能发请求”，没有真实模型结果。
- 没有 token/费用统计、调用日志、超时重试策略、提示词版本管理。
- 配置文件是单机单用户，没有密钥托管或多用户隔离。

### 3.9 UI 与导航 — A / C

**已闭环**

- 6 个功能页 + 报告中心 4 个页签；深色主题、卡片、吸顶、空状态、深链接。
- 首页模块配置有 2 项回归测试。

**边界**

- 除首页配置外，UI 没有进入 pytest；`tests` 里没有 AppTest。
- 主题 CSS 约 1050 行，没有视觉回归测试。
- 页面状态依赖 `st.session_state`，重启/换浏览器会丢失。
- 没有移动端专门适配；窄屏只靠 Streamlit 自动堆叠。

### 3.10 运行与安全 — C / D

- 单进程 Streamlit + SQLite，适合本地单用户。
- 没有登录、角色、权限、审计日志、数据脱敏、API、任务队列。
- 迁移不会在 `get_connection()` 自动执行，需要显式 `initialize_database()`；升级后不重启可能读不到新表。
- 没有生产部署、备份、监控、并发写入治理。

## 4. 真完成 / 未验证 / 初步实现 / 仅接口

### 真正完成（可以按现有边界使用）

- 反馈导入（小文件）与 SQLite 持久化。
- 统一 Evidence 模型、EvidenceRepository、关联引擎、证据上下文。
- 规则诊断、LLM 引用校验管道、无 LLM 回退。
- 问题聚类（≤500 条）、簇报告、诊断报告归档。
- 报告处理状态、批量处理、锁定/重开。
- 周期报告生成、归档、检索、下载、删除。
- LLM 配置双通道与连接测试。
- 首页、六个功能页、报告中心四页签的本地交互。

### 有代码但未真实验证

- Elasticsearch 连接器（mock 6 项）。
- Prometheus 连接器（mock/样例 12 项）。
- LLM 线上诊断（注入式测试，无真实 Key）。
- 周期报告 UI（手工 AppTest，无自动化）。
- 窄屏/主题视觉（手工截图，无视觉回归）。

### 初步实现（有明确上限或缺口）

- 反馈分析的现象/功能分布：只算前 500 条。
- 问题聚类：只算前 500 条，无人工纠错。
- 证据关联：候选 200 / 结果 50 上限，阈值写死。
- 诊断下一步：直播场景硬编码，非直播场景泛化。
- 周期报告：无跟踪、无定时、无订阅。
- 报告列表：limit 100/200，无分页 UI。

### 仅接口 / 尚未开始

- OpenSearch、Loki、Jaeger、Tempo。
- 故障场景配置模型（本次只设计，不实现）。
- 人工合并/拆分聚类并写回。
- 根因候选、历史故障检索、知识库。
- 后台导入任务、任务队列、断点续传。
- 登录/权限/审计/多工作空间/API。

## 5. 最值得先修的边界

1. **500 条静默截断**：反馈分析和聚类都只读前 500 条，超过后数字会“看起来正常但实际不全”。应先加分页/时间窗/全量聚合，至少在 UI 明示“仅统计最近 500 条”。
2. **诊断步骤领域硬编码**：`rtmp` / `cdn` 只适用于直播；非直播反馈需要场景化 runbook，否则诊断建议没有领域价值。
3. **聚类不可纠错**：不能合并/拆分/改名，自动簇无法成为稳定问题主数据。
4. **外部连接器未联调**：ES / Prometheus 只能当“代码已写”，不能当“已接入”。
5. **周期报告不可跟踪、不定时**：目前是手动汇总，不是周期性监控。
6. **导入内存与 NaN 问题**：大文件会顶内存，空字段会触发 JSON 序列化失败；真实批量导入前必须处理。
