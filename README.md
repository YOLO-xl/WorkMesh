# WorkMesh

WorkMesh 是一个面向企业技术支持与生产问题排查场景的 AI 工作台。

## 核心目标

- 统一接入用户反馈、工单、日志和监控数据。
- 对反馈和工单进行统计分析。
- 关联多源证据，辅助定位生产问题。
- 为 AI 辅助诊断和知识检索提供数据基础。

## 页面导航

首页是独立的工作台层（不进入侧边栏模块列表），默认进入：
顶栏（搜索 / 通知 / 帮助 / 个人入口）→ 欢迎区与常用入口 → 分组的模块卡片 → 工作动态。
模块卡片整块可点击，顶部搜索框可按模块名、标签或反馈编号快速定位。

| 页面 | 作用 |
| --- | --- |
| 数据接入 | 导入反馈、字段映射、质量校验 |
| 证据关联 | 接入日志 / 指标 / 变更，围绕反馈算关联 |
| 问题聚类 | 同类反馈自动成簇，看影响面与现象分布；无错误码也能按现象归并 |
| 反馈分析 | 版本、平台、错误码分布与趋势；反馈全景看现象与功能分布 |
| 单条诊断 | 针对单个反馈生成带引用的诊断报告 |
| 报告中心 | 单条诊断与簇报告归档、检索、处理状态 / 负责人 / 备注、下载与删除；同一页配置 LLM 接入 |

页面支持深链接：`?page=问题聚类` 直接进模块，`?view=home` 回首屏。

## 当前已实现

- Streamlit 基础工作台与页面导航。
- CSV / Excel 数据导入、字段映射和质量检查。
- SQLite 数据持久化及 Repository 数据访问层。
- 反馈数据基础统计分析。
- Connector 统一连接器接口与注册中心。
- Elasticsearch 日志连接器初版。
- Prometheus 指标连接器（样例指标接入，未对真实实例联调）。
- 问题聚类：有错误码按码归并，无错误码按「现象 + 功能」加权归并，并保留未归类池。
- 反馈全景：现象分布、功能提及分布与按现象下钻。
- 规则诊断 + 可选 LLM 诊断：结论必须引用证据，引用不存在会被打回。
- 诊断报告中心：单条诊断可自动或手动归档，按关键词 / 生成方式检索、下载 Markdown、删除；
  内容 hash 去重，同一反馈同一结论不重复入库。
- 问题簇报告：问题聚类页一键汇总整簇，含影响面、时间集中度、现象 / 版本 / 平台分布、
  可选 3 / 5 / 8 条成员诊断与共性证据；报告中心「簇报告」页签支持筛选、下载、删除，
  同一问题的多次快照可看反馈 / 用户 / 证据变化。
- 报告处理闭环：两类报告统一「待处理 / 已处理 / 已忽略」状态、负责人与备注，
  支持按状态筛选，报告中心指标直接暴露待处理数量。
- 批量处理：按当前筛选结果一次更新多份报告，可先按产品 / 严重度缩小范围，
  再统一标记已处理或已忽略。
- 报告标题直接显示处理状态；已处理 / 已忽略默认锁定，需「重新打开处理」后才能修改。
- LLM 配置双通道：环境变量优先、本机配置文件兜底；支持保存、测试连接、清除，
  文件以 0600 权限存放，诊断服务即时读取。
- LLM 服务商预设：OpenAI、DeepSeek、通义千问、Kimi、智谱 GLM、SiliconFlow、
  本地 Ollama、自定义网关；切换后自动填入兼容地址与常用模型。
- 统一 Evidence 证据模型：日志、反馈等接入后转换为同一结构并持久化。
- 证据关联分析：按 Trace ID / Request ID / UID / 错误码 / 服务与时间窗口计算关联分数。
- 「证据关联」页面：证据接入、生成问题上下文、回看已保存关联。
- 数据库版本化 Migration（v1 → v5），新增诊断报告表、问题簇报告表与报告处理记录表。
- 自动化测试。

## 本地运行

安装依赖：

```bash
pip install -r requirements.txt
```

启动工作台：

```bash
streamlit run app.py
```

运行测试：

```bash
pytest -q
```

配置可选能力（LLM 诊断 / 外部数据源）有两种方式，环境变量优先：

```bash
cp .env.example .env   # 填入 OPENAI_API_KEY、OPENAI_BASE_URL 等
```

或启动后进入「报告中心 → LLM 配置」，先选服务商（OpenAI / DeepSeek / 通义千问 /
Kimi / 智谱 / SiliconFlow / 本地 Ollama / 自定义），地址与模型会自动带出，
再填 API Key 与超时；点「保存配置」写入 `.workmesh/llm.local.json`
（权限 600，已被 `.gitignore` 忽略）。
页面上可直接「测试连接」，也可以「清除本机配置」。

## 快速体验证据关联

1. 启动工作台，进入「数据接入」，导入 `data/sample/feedback_sample.csv`。
2. 进入「证据关联」→「证据接入」，点击「接入内置样例日志」
   （读取 `data/sample/log_sample.jsonl`，共 10 条日志）。
3. 切到「证据关联」页签，选择反馈 `F001`（UID 10086231 / E1001），
   时间窗口 30 分钟，生成上下文。
4. 预期结果：候选证据 5 条、强关联日志 2 条、同 UID 的其他反馈 1 条，
   事实区显示 UID / 错误码 / 服务一致项。
5. 可选：在同一页切到「Prometheus 指标」，点「接入内置指标样例」
   （`data/sample/prometheus_sample.json`），再生成上下文，
   会多出 4 条指标「上下文证据」，总关联 6 条。

## 快速体验问题聚类

1. 侧边栏进入「问题聚类」，默认最小簇规模为 2。
2. 看簇列表：每张卡片给出反馈数、涉及用户、主要现象、时间范围与证据量。
3. 点「查看簇详情」，查看现象分组与成员反馈，可导出簇成员 CSV。
4. 点「用代表反馈做单条诊断」，直接带这条反馈跳到「单条诊断」页。

聚类口径：同一产品的同一错误码视为同一类问题；错误码缺失时，先把描述归约成
「现象 + 功能实体」，再按加权分归并；识别不出的反馈进「未归类池」，不强行归类。
簇只表示「看起来是同一批问题」，不是根因结论。

想验证无错误码场景，可在「数据接入」导入
`data/sample/feedback_sample_no_code.csv`（100 条不带错误码的样例）。

## 快速体验智能诊断

1. 进入「智能诊断」，选择反馈 `F001`，窗口 30 分钟。
2. 点「生成诊断」，得到带证据引用的报告：
   事实区只写字段一致项，其余全部标为推断，每条结论附依据。
3. 未配置 LLM 时使用规则诊断；在「报告中心 → LLM 配置」或环境变量
   `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` 配置后勾选 LLM，
   模型只做润色与推理，引用不存在的证据会被打回并退回规则诊断。
4. 报告可下载为 Markdown；勾选「生成后自动归档」会存入「报告中心」，
   在那里按关键词检索、展开全文、下载或删除。
5. 想看整簇：在「问题聚类」展开一个簇，选择抽样 3 / 5 / 8 条，点「生成簇报告」；
   报告会抽样做单条诊断，再汇总影响面、现象分布与共性证据，归档到
   「报告中心 → 簇报告」，并可对比同一问题的上一份快照。

设计说明见 `docs/EVIDENCE_MODEL.md`，诊断口径见
`services/diagnosis_service.py` 顶部注释。

## 设计原则

1. 统一接口：不同外部系统通过 Connector 接入。
2. 证据优先：分析结论应关联原始数据和证据，事实与假设分开标注。
3. 保留原始数据：标准化处理不覆盖原始记录。
4. 只读优先：外部系统接入以查询和分析为主。
5. 渐进扩展：先完善数据与连接器基础，再扩展 AI 诊断能力。
