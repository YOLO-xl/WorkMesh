# WorkMesh

> 面向企业技术支持与生产问题排查的 AI 工作台。
>
> 当前版本：`v0.7.0-dev` · 8 个功能页面 · 152 项自动化测试

WorkMesh 把用户反馈、日志、指标和变更记录收敛到同一套 Evidence 模型，围绕一条反馈完成证据关联、故障场景判定、诊断报告归档和原始记录追溯。

## 项目定位

- 统一接入用户反馈、日志、指标和变更记录。
- 对反馈做统计分析，识别影响面与集中趋势。
- 关联多源证据，辅助定位生产问题。
- 让每条诊断结论都能回到具体证据和原始记录。

## 当前边界

这些是已知上限，不是隐藏问题：

| 边界 | 当前状态 |
| --- | --- |
| 真实 Elasticsearch / Prometheus | 已在本地 Docker 完成 ES 9.1.0 / Prometheus 2.55.1 联调；生产环境的认证、TLS、字段映射与脱敏审计仍未做 |
| ES 查询能力 | 已支持 uid / error_code / trace_id / request_id / service / level term 过滤、时间窗、关键词、`search_after` 翻页、aggregations、highlight，并保留 `_index` / `_id` / `_score`；暂无任意 DSL 透传 |
| Prometheus 历史时间窗 | Prometheus 会拒收明显偏历史或偏未来的显式样本；连接器默认查当前态，历史窗口需由 `use_window` 显式开启 |
| 场景统计口径 | 覆盖率 / blocked 率只在「故障场景」页批量评估中提供，尚未写回簇报告与周期报告；跨来源同一条日志暂不归并 |
| 其他可观测系统 | OpenSearch、Loki、Jaeger、Tempo 尚未接入 |
| LLM 评测 | 已验证 DeepSeek 单模型；暂无多模型对比、提示词评测、限流重试与成本控制 |
| 证据关联 | 只基于标识与时间窗口，不做语义相似度 |
| 聚类与分析范围 | 当前按前 500 条反馈计算，支撑万级增量前需要分块与索引优化 |
| 大文件导入 | 仍是同步整文件读入，没有分块与后台任务，受内存限制 |
| 场景数据源 | `connector` 依赖注入 provider；`report_history` / `knowledge` 尚未接入 |

## 快速体验

### 1. 证据关联

1. 进入「数据接入」，导入 `data/sample/feedback_sample.csv`。
2. 进入「证据关联」→「证据接入」，点击「接入内置样例日志」
   （`data/sample/log_sample.jsonl`，10 条日志）。
3. 切到「证据关联」页签，选择反馈 `F001`（UID 10086231 / E1001），窗口 30 分钟，生成上下文。
4. 仅日志阶段：2 条同 UID 日志为强关联，另有 1 条同 UID 反馈。
5. 可选接入 Prometheus 指标样例（`data/sample/prometheus_sample.json`）后重新生成：
   候选证据 9 条、关联 6 条、强关联 2 条、上下文指标 4 条，覆盖 2 类来源。

### 2. 故障排查

1. 进入「故障排查」，点击「运行内置样例」。
2. 页面会用 `F001`（直播SDK / E1001 / UID 10086231）串起：
   - 本地反馈 1 条；
   - 同 UID 的直播日志 2 条（同一个 `trace-0001`）；
   - 4 条直播指标（播放器初始化失败率 0.182、进入房间 P99 4280ms 等）。
3. 场景命中 `live.enter_room_failure`，状态 `verified`，置信度 `medium`；
   结论证据都能在证据链里找到，`all_conclusions_traceable=True`。
4. 可选：展开「外部数据源（可选）」，填 Elasticsearch / Prometheus 地址后重跑；
   连接失败会显示「不可用」，不会用本地数据补齐。

> 本机可用 Docker 起 ES 9.1.0 与 Prometheus 2.55.1，真实联调已跑通；
> 生产集群仍需补认证、TLS、字段映射与访问审计。

### 3. 问题聚类

1. 侧边栏进入「问题聚类」，默认最小簇规模为 2。
2. 簇列表展示反馈数、涉及用户、主要现象、时间范围与证据量。
3. 点「查看簇详情」看现象分组与成员反馈，可导出簇成员 CSV。
4. 点「用代表反馈做单条诊断」，直接带这条反馈跳到「单条诊断」页。

聚类口径：同一产品的同一错误码视为同一类问题；错误码缺失时，先把描述归约成「现象 + 功能实体」，再按加权分归并；识别不出的反馈进入「未归类池」，不强行归类。簇只表示「看起来是同一批问题」，不是根因结论。

验证无错误码场景可导入 `data/sample/feedback_sample_no_code.csv`（100 条无错误码样例）。

### 4. 单条诊断

1. 进入「单条诊断」，选择反馈 `F001`，窗口 30 分钟。
2. 点「生成诊断」：事实区只写字段一致项，其余标为推断，每条结论附证据 ID。
3. 未配置 LLM 时走规则诊断；配置后勾选 LLM，模型只做润色与推理，引用不存在的证据会被打回并退回规则诊断。
4. 报告可下载 Markdown；勾选「生成后自动归档」会存入「报告中心」。
5. 想看整簇：在「问题聚类」展开一个簇，选择抽样 3 / 5 / 8 条，点「生成簇报告」；
   报告会汇总影响面、现象分布与共性证据，归档到「报告中心 → 簇报告」，并可对比上一份快照。

设计说明见 `docs/EVIDENCE_MODEL.md`，诊断口径见 `services/diagnosis_service.py` 顶部注释。

### 5. 故障场景运营

1. 进入「故障场景」，首屏看启用场景、配置错误、外部连接器场景三个指标。
2. 展开「外部连接器（可选）」并勾选后，填 ES（默认 `http://localhost:9200`）与 Prometheus（默认 `http://localhost:9091`），场景评估会按 `connector` source 真实取数。
3. 「覆盖评估」选择最近 50 / 100 / 500 条，点「评估场景覆盖」：看覆盖率、已验证、部分完成、阻塞与具体场景验证率。
4. 下方「单条试跑」选一条反馈，看命中场景、匹配理由、排查步骤、缺失源和下一步动作。
5. 不勾选外部连接器时，只使用本地反馈与已入库证据；外部源缺失会标为「未验证」，不补造数据。

## 设计原则

1. **统一接口**：不同外部系统通过 Connector 接入。
2. **证据优先**：分析结论关联原始数据和证据，事实与假设分开标注。
3. **保留原始数据**：标准化处理不覆盖原始记录。
4. **只读优先**：外部系统接入以查询和分析为主。
5. **渐进扩展**：先完善数据与连接器基础，再扩展 AI 诊断与自动化能力。
